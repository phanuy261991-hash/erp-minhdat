## 2026-08-02 (Import/Export Excel cho Sản phẩm)

> Người dùng yêu cầu chức năng import/export Excel tại trang Sản phẩm: import cho phép tải file mẫu, báo lỗi rõ dòng nào/lỗi gì. Trước khi code đã hỏi 3 câu hỏi kiến trúc qua AskUserQuestion (mã trùng xử lý sao, còn lỗi thì nhập phần nào, export xuất theo phạm vi nào) — chi tiết `docs/DECISIONS.md`.

- **Dependency mới**: `exceljs@^4.4.0` (đọc/ghi file `.xlsx` ở backend — không dùng `xlsx`/SheetJS vì bản npm có lỗ hổng bảo mật đã biết chưa được vá), `multer@^2.2.0` (parse `multipart/form-data`, `memoryStorage()` không ghi file tạm ra đĩa, giới hạn 5MB). `npm audit` báo 2 lỗ hổng mức trung bình (`uuid` — dependency gián tiếp của `exceljs`, liên quan buffer do người gọi cung cấp, không áp dụng với cách `exceljs` dùng nội bộ) — chấp nhận, không hạ cấp `exceljs` xuống bản rất cũ (`npm audit fix --force` sẽ ép về `exceljs@3.4.0`, mất nhiều năm bugfix).
- **`backend/routes/products.routes.js`** (thêm 3 route, đặt TRƯỚC `GET /:id` vì Express khớp `/:id` với bất kỳ đoạn đường dẫn 1 từ nào kể cả `import-template`/`import`/`export` nếu đăng ký sau):
  - `GET /import-template` (quyền `kho`): sinh file mẫu 2 sheet — "San pham" (6 cột đúng thứ tự form: Mã*/Tên*/Đơn vị tính*/Giá bán*/Giá vốn/Ngưỡng cảnh báo tồn kho thấp) và "Hướng dẫn" (quy tắc nhập).
  - `POST /import` (quyền `kho`, `upload.single('file')`): đọc file bằng `ExcelJS.Workbook().xlsx.load()`, validate từng dòng (mirror đúng rule của `POST /` hiện có: mã/tên/đơn vị/giá bán bắt buộc — cộng thêm kiểm tra Giá vốn/Ngưỡng cảnh báo phải là số hợp lệ nếu có nhập, khác form thường vốn âm thầm quy giá trị rác về 0 vì bulk import từ file dễ gõ nhầm hơn nên cần báo lỗi rõ thay vì im lặng sai). **Toàn bộ file phải hợp lệ mới ghi vào DB** (theo quyết định người dùng) — nếu có bất kỳ dòng lỗi nào, trả `422` kèm mảng `{row, message}`, không insert gì cả; nếu hợp lệ hết, insert toàn bộ trong 1 `db.transaction()`. Mã trùng (với DB hoặc trùng nhau trong chính file) bị báo lỗi, không tự động cập nhật (không upsert).
  - `POST /export` (mở cho mọi tài khoản đã đăng nhập, giống `GET /products` — không riêng quyền `kho`): nhận `{ ids: [...] }` từ frontend, xuất **đúng** những sản phẩm đó theo **đúng thứ tự** đã gửi lên — đảm bảo khớp chính xác với danh sách người dùng đang thấy trên giao diện (có áp dụng tìm kiếm), không tự suy đoán bộ lọc ở backend.
  - Thêm error handler riêng cho `multer.MulterError` (vd vượt 5MB) ở cuối router — trả JSON `{error}` thay vì để Express rơi về trang lỗi HTML mặc định (dự án chưa có global error handler).
- **`frontend/products.html`**: 2 nút mới trong `.page-header-actions` ("Nhập Excel"/"Xuất Excel", dùng icon có sẵn `arrowUpTray`/`arrowDownTray`, không cần thêm icon mới) + modal `#import-modal` (link tải file mẫu, chọn file, alert lỗi chung/thành công, bảng "Dòng"/"Lỗi" khi có lỗi — tái dùng `.data-table`/`.alert-error`/`.alert-success`/`.modal-subtitle` có sẵn, không cần CSS mới ngoài 1 rule scoped cho anchor "Tải file mẫu").
- **`frontend/assets/products.js`**: `btnExportProducts` gọi `getVisibleProducts()` (hàm lọc/sắp xếp đã có sẵn cho ô tìm kiếm) lấy đúng danh sách đang hiển thị, POST `{ids}` tới `/api/products/export`, nhận `blob` rồi tự tạo link tải xuống. `btnSubmitImport` gửi `FormData` tới `/api/products/import` — cả 2 đều dùng `fetch` trực tiếp thay vì `apiFetch()` (hàm dùng chung luôn gán cứng `Content-Type: application/json`, sẽ phá hỏng boundary của `multipart/form-data` và không parse được response dạng blob).
- Test qua API (curl, xem chi tiết `docs/DECISIONS.md`): file có dòng lỗi bị chặn đúng (báo đúng số dòng + nội dung lỗi), file hợp lệ nhập đúng số lượng, nhập lại mã đã tồn tại bị chặn đúng, file không phải Excel thật/thiếu file bị chặn đúng, tài khoản Kế toán (không có quyền `kho`) bị chặn 403 khi gọi `import`/`import-template` nhưng vẫn gọi `export` được (đúng thiết kế, giống mức mở của `GET /products`).
- Test qua trình duyệt thật (Chrome headless điều khiển CDP thô — dự án không có Playwright, viết script Node dùng `WebSocket` built-in gọi thẳng Chrome DevTools Protocol, kèm `DOM.setFileInputFiles` để giả lập chọn file qua input thật và `Browser.setDownloadBehavior` để bắt file tải về, có chụp ảnh màn hình xác nhận trực quan): mở modal Nhập Excel, chọn file có lỗi → bảng lỗi hiển thị đúng dòng/nội dung; chọn file hợp lệ → thông báo "Đã nhập thành công 2 sản phẩm" + danh sách sản phẩm tự làm mới; bấm "Xuất Excel" → trình duyệt tải đúng file `.xlsx` chứa đúng nội dung đang hiển thị; không có lỗi console trong toàn bộ luồng.
